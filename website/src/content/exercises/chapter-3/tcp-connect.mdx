
از tracepointها برای hook زدن به syscallها استفاده کردیم. حالا بیایید **kprobe**ها را یاد بگیریم — اتصال به توابع داخلی کرنل.

## Kprobes vs tracepoints

**Tracepoint**ها hookهای پایدار و مستند در رویدادهای مشخص کرنل هستند (ورود/خروج syscall، زمان‌بندی و غیره). زمینه‌ای ساختاریافته ارائه می‌دهند:
```c
SEC("tracepoint/syscalls/sys_enter_connect")
int trace(struct trace_event_raw_sys_enter *ctx) {
    u32 fd = ctx->args[0];  // Predefined fields
}
```

**Kprobe**ها به هر تابع کرنل از طریق نام وصل می‌شوند.

این مکانیزم انعطاف‌پذیرتر است، اما kprobeها بخشی از API پایدار کرنل نیستند و می‌توانند بین نسخه‌های کرنل تغییر کنند. علاوه بر این، 'context' تعریف‌شده‌ای ارائه نمی‌دهند؛ باید نوع و ترتیب آرگومان‌ها را از سورس کرنل پیدا کنیم.

## Why kprobes?

Tracepointها رویدادهای مشخص را در معرض قرار می‌دهند. Kprobeها به ما اجازه می‌دهند عمیق‌تر به درون کرنل hook بزنیم. مثلاً syscall `connect()` برای سوکت‌های non-blocking بلافاصله برمی‌گردد، اما `tcp_finish_connect()` زمانی فراخوانی می‌شود که دست‌دهی TCP واقعاً کامل شود.

## Accessing function arguments

Kprobeها `struct pt_regs *ctx` دریافت می‌کنند — رجیسترهای خام CPU. از ماکروها برای استخراج آرگومان‌ها استفاده کنید:

```c
PT_REGS_PARM1(ctx)  // First parameter
PT_REGS_PARM2(ctx)  // Second parameter
PT_REGS_PARM3(ctx)  // Third parameter
// up to 8
```

امضای `tcp_finish_connect` را می‌توان در `net/ipv4/tcp_input.c` پیدا کرد که عبارت است از
```c
void tcp_finish_connect(struct sock *sk, struct sk_buff *skb);
```

بنابراین برای دسترسی به `struct sock*` باید **اولین** آرگومان را cast کنیم:
```c
struct sock *sk = (struct sock *)PT_REGS_PARM1(ctx);
```

## The challenge

برنامه‌ای به سرور راه‌دور وصل می‌شود. syscall `connect()` مقدار `-EINPROGRESS` (non-blocking) برمی‌گرداند، اما اتصال با موفقیت کامل می‌شود.

### Socket properties

می‌توانید ویژگی‌های سوکت را با `bpf_probe_read_kernel` بخوانید. فیلدهای مرتبط:

```c
struct sock {
    struct sock_common __sk_common;  // Common socket info
    // ...
};

struct sock_common {
    u16 skc_dport;   // Destination port
    u32 skc_daddr;   // Destination IPv4 address
    // ...
};
```

به یاد داشته باشید پورت‌ها big endian هستند، پس باید از `bpf_ntohs` برای تبدیل استفاده کنید.
