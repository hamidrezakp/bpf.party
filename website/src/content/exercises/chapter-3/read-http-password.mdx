در تمرین قبلی از kprobeها برای ردیابی تکمیل اتصال TCP استفاده کردیم. حالا داده‌های HTTP را هنگام ارسال intercept می‌کنیم.

می‌توانستیم به syscall `sendto()` وصل شویم، اما آن فراخوانی‌های [vsock](https://gitlab.com/vsock/vsock) را هم intercept می‌کند که شامل فراخوانی‌های `DEBUG_*` است و تجربه‌ای ناخوشایند می‌سازد.

علاوه بر این، اصلاً با فصل `kprobe` جور درنمی‌آمد!

به‌جای آن به `tcp_sendmsg()` وصل می‌شویم که فقط برای ترافیک TCP فراخوانی می‌شود.


## Reading data from tcp_sendmsg

امضای `tcp_sendmsg` را می‌توان در `net/ipv4/tcp.c` پیدا کرد که عبارت است از:

```c
int tcp_sendmsg(struct sock *sk, struct msghdr *msg, size_t size);
```

و می‌توانیم به بافر userspace از پارامتر `msg` دسترسی پیدا کنیم، اما کمی پیچیده است.

تعریف ساده‌شده `struct msghdr`:

```c
struct msghdr {
    struct iov_iter msg_iter;  // Iterator containing buffer info
    // ...
};

struct iov_iter {
    union {
        struct iovec __ubuf_iovec;  // Userspace buffer base/len
        // ...
    };
};

struct iovec {
    void *iov_base;
    u64   iov_len;
};
```

پس بافر userspace را می‌خوانیم که آدرس آن در `msg->msg_iter->__ubuf_iovec.iov_base` ذخیره شده.

به یاد داشته باشید نمی‌توانیم اشاره‌گرها را مستقیماً dereference کنیم، پس باید هر سطح indirection را دستی بخوانید. فضای آدرس هر اشاره‌گر را در نظر بگیرید.


## HTTP request structure

درخواست‌های HTTP متنی هستند:

```text
POST /api/data HTTP/1.1
Host: example.com
Authorization: Bearer secret_token_here
Content-Type: application/json
```

هدرها با `\r\n` (CRLF) از هم جدا می‌شوند. هر هدر به شکل `Name: Value` است.

در گذشته، کار روی هر پروتکل متنی در eBPF _فوق‌العاده_ خسته‌کننده بود. خوشبختانه از [ژوئن ۲۰۲۵](https://lore.kernel.org/all/4b008a6212852c1b056a413f86e3efddac73551c.1750917800.git.vmalik@redhat.com/) می‌توانیم برخی عملیات رشته‌ای را مستقیماً انجام دهیم.

در این تمرین از دو تابع استفاده می‌کنیم:

- `bpf_strstr(char *haystack, char *needle)`: زیررشته را پیدا می‌کند، index برمی‌گرداند یا در صورت خطا مقدار منفی
- `bpf_strchr(char* str, char c)`: کاراکتر را پیدا می‌کند، index برمی‌گرداند یا در صورت خطا مقدار منفی

مثلاً،
```c
int auth_pos = bpf_strstr(buf, "Authorization: Bearer ");
```
`auth_pos` در صورت یافتن، موقعیت needle را دارد.

با کمی محاسبه می‌توانید بفهمید token از کجا باید شروع شود، و از آنجا تا انتهای خط (با `\r` مشخص شده) بخوانید.

برای رسیدن به انتها می‌توانید از
```c
int token_pos = bpf_strchr(&buf[token_start], '\r');
```
استفاده کنید که موقعیت **اولین** `\r` را از `token_ptr` برمی‌گرداند.
