این پلتفرم یک محیط پیکربندی‌شده و تمرین‌هایی برای یادگیری eBPF فراهم می‌کند.

ویرایشگر کد شما را به‌صورت محلی هم‌زمان با تایپ کامپایل می‌کند، اما می‌توانید با کلیک روی دکمه <ControlButton title="بررسی کد هنگام تایپ" style={{display: "inline"}}><Braces size={14} /></ControlButton> این قابلیت را غیرفعال کنید. خطاهای کامپایل در بخش خروجی نمایش داده می‌شوند.

در ویرایشگر تایپ کنید و ببینید چگونه واکنش نشان می‌دهد، سپس روی «اجرا» کلیک کنید تا کدتان روی سرور اجرا شود.

اگر حالت Vim را ترجیح می‌دهید، دکمه <ControlButton title="حالت Vim" style={{display: "inline"}}><Keyboard size={14} /></ControlButton> آن را فعال یا غیرفعال می‌کند.

## میانبرهای صفحه‌کلید

- <span dir="ltr"><kbd>Ctrl</kbd>+<kbd>Enter</kbd></span> کد را اجرا می‌کند.
- <span dir="ltr"><kbd>Ctrl</kbd>+<kbd>Click</kbd></span> روی تعریف نوع‌ها (`my_struct`, `trace_event_raw_sched_process_exec`) پنجره تعریف نوع را نشان می‌دهد

## ابزارهای اشکال‌زدایی

چندین ماکرو `DEBUG_` برای نمایش داده از برنامه‌های شما وجود دارد.
هر ماکرو آرگومان اول خود را به‌صورت یک label (ثابت رشته‌ای) می‌گیرد.

- `DEBUG_NUM(label, num)` هر عددی را می‌پذیرد، مانند `u32` یا `ssize_t`
- `DEBUG_STR(label, buf)` به buf با اندازه ثابت نیاز دارد، مانند `char[64]`
- `DEBUG_STR_LEN(label, ptr, len)` هر pointer را می‌پذیرد و `len` بایت را debug می‌کند
- `DEBUG_STRUCT(label, struct)` هر struct را _به‌صورت مقدار_ می‌پذیرد

## ارسال پاسخ‌ها

برای حل تمرین‌ها باید پاسخ‌ها را مستقیماً از کد خود با `SUBMIT_NUM(answer)`، `SUBMIT_STR(answer)` یا `SUBMIT_STR_LEN(answer, len)` ارسال کنید.

برنامه eBPF شما روی چندین رویداد فعال می‌شود، بنابراین باید فراخوانی‌های `SUBMIT_X` خود را محافظت کنید، چون چند ارسال همه پاسخ‌ها را باطل می‌کند.

وقتی از `SUBMIT_STR` استفاده می‌کنید، بایت‌های null انتهایی trim می‌شوند، اما داده‌های اضافی انتهایی نه. وقتی نمی‌توانید null termination را تضمین کنید، از variant `SUBMIT_STR_LEN` استفاده کنید.

این تمرین را با uncomment کردن `SUBMIT_STR("the answer");` حل کنید.
