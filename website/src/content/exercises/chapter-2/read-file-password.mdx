در تمرین قبلی، **همه** فراخوانی‌های `read()` را گرفتیم. اما اگر فقط به خواندن از یک فایل خاص مثل `/tmp/password` علاقه داشته باشیم چه؟

مشکل این است که `read()` روی file descriptor کار می‌کند، نه نام فایل. وقتی یک فرایند `open("/tmp/password")` را صدا می‌زند، کرنل یک file descriptor (fd) برمی‌گرداند — یک عدد یکتا برای هر فرایند (مثل `4`). فراخوانی‌های بعدی read از آن عدد استفاده می‌کنند: `read(4, buf, ...)`.

وقتی syscall `read()` را می‌بینیم، فقط به `fd` دسترسی داریم. نام فایل از بین رفته است.

برای فیلتر کردن readها بر اساس نام فایل، باید syscallهای `open()` و `read()` را همبسته کنیم: در زمان open بفهمیم کدام fdها مربوط به `/tmp/password` هستند، سپس هنگام intercept کردن read از آن اطلاعات استفاده کنیم.

## همبسته‌کردن open و read

باید چهار رویداد را hook کنیم و اطلاعات را بین آن‌ها رد کنیم:

وقتی یک فرایند `/tmp/password` را باز می‌کند:
1. **ورود open** — pathname را می‌بینیم و می‌توانیم بررسی کنیم آیا با هدف ما مطابقت دارد
2. **خروج open** — fd تخصیص‌یافته به این فایل را می‌گیریم

وقتی همان فرایند از آن fd می‌خواند:

3. **ورود read** — می‌بینیم از کدام fd خوانده می‌شود و بافر مقصد کجاست
4. **خروج read** — می‌بینیم چند بایت نوشته شده

چالش این است که این نقاط را به هم وصل کنیم: در مرحله ۳ چطور بفهمیم fd `4` همان fd مرحله ۱ است که برایمان مهم است؟

## ردیابی با سه map

از سه map استفاده می‌کنیم تا اطلاعات را در این pipeline رد کنیم.

**نشانگر موقت در طول open:**

در ورود open، PIDهایی که `/tmp/password` را باز می‌کنند در `open_curr_fd_interesting` علامت‌گذاری می‌کنیم. در خروج، این علامت را بررسی می‌کنیم تا بفهمیم fd برگشتی برایمان جالب است یا نه.

می‌توانیم با خیال راحت PID را به‌عنوان کلید استفاده کنیم چون thread در طول syscall مسدود است — تا این یکی تمام نشود، نمی‌تواند `open()` دیگری بزند.

**ردیابی پایدار fdهای جالب:**

وقتی فهمیدیم PID `123` برای `/tmp/password` fd `4` گرفته، باید این ارتباط را به خاطر بسپاریم. بعداً وقتی `read(4, ...)` را می‌بینیم، می‌توانیم بررسی کنیم آیا `(123, 4)` در map ما هست.

این اولین کلید composite ما را می‌طلبد:

```c
struct pid_fd_key {
    u64 pid;
    u32 fd;
};

struct {
    __uint(type, BPF_MAP_TYPE_HASH);
    __uint(max_entries, 1024);
    __type(key, struct pid_fd_key);
    __type(value, u8);   // marker
} open_interesting_fds SEC(".maps");
```

هم PID و هم FD را در کلید می‌خواهیم چون یک فرایند می‌تواند همزمان چند file descriptor باز داشته باشد. fd `4` ممکن است `/tmp/password` باشد در حالی که fd `5` مربوط به `/etc/config` است.

**ذخیره موقت در طول read:**

مثل تمرین قبلی، `read_curr_fd_buf` را تعریف می‌کنیم تا اشاره‌گر بافر را از ورود read تا خروج read ذخیره کند و PID را به‌عنوان کلید استفاده کنیم.
